FUMES -- changes


0.1.9
=====

  * A LICENCE, AT LAST. The repo went public with none, which means all rights
    reserved by default whatever the mod page says -- so nobody could legally fork
    it, read it into their own mod, or do the obvious thing with a mod's source.
    MIT now, stated in LICENSE at the root of the repo and shipped as LICENCE.txt
    in this zip, which the 0.1.8 zip did not carry.

  * The README no longer tells you to install ScriptHookVDotNet 3.9.0.0. That
    requirement stopped being true in 0.1.8 -- the build vendors 3.6.0 so the mod
    loads on 3.6 and every nightly since -- but the install step never followed the
    build down, and every "I cannot find a 3.9 anywhere" message traces back to it.
    It says what is actually needed now: any ScriptHookVDotNet 3 from 3.6.0 up.

  * No code changed. The dll in this zip does the same thing 0.1.8's did; if you
    are running 0.1.8 happily there is nothing here you need.

  * 218 settings in the ini, unchanged.


0.1.8
=====

  * THE FUEL GAUGE IS ONE OF BARE MINIMUM'S BARS NOW. The same width, the same
    height, the same black surround and the same mark beneath it -- and it stands
    IN that row rather than beside it, taking its place among the health, food,
    thirst and sleep bars and following them if the row moves to the other side of
    the minimap. Nothing to set up. Without Bare Minimum installed the gauge sits
    where it always did, and HUD.ManualX = true pins it by hand whatever else is
    running.

    (Written up after the fact: 0.1.8's notes listed the two fixes below and said
    nothing about the rework, which is most of what went into it.)

  * The fuel moves the way the bars beside it do. It settles at a stop and leans
    the right way round under braking, and the specks rise through it instead of
    falling -- slower and wider than they used to. A bevel down each side gives the
    column its depth; HUD.Relief = 0 takes it off. Nothing sweeps over the fuel
    itself: the depth and the rising specks are the whole of it.

  * The gauge hides on the wasted screen and through cutscenes, with the rest of
    the HUD.

  * On a bar this narrow the stepped surface quantised into a staircase that
    crawled as the level changed. Under sixteen pixels wide it is one column now,
    which is the honest answer at that size.

  * THE GAUGE STOPPED TAKING OTHER MODS' PANELS OFF THE SCREEN. Rectangles come
    out of one list the game keeps for the whole machine, and once it is full
    everything handed over after that is dropped -- so the script that pays for a
    busy frame is whichever draws LAST, whatever it drew. The fuel's gradient was
    a band every four pixels, up to sixty-four of them, and with the other HUDs
    beside the minimap doing the same there was nothing left: another mod's phone
    came up in a car with no background, because its screen is a rectangle.

    A band every fourteen pixels now, which on a bar this narrow looks the same,
    and nothing under half a pixel is drawn at all. The gauge also counts what it
    spends and writes the worst frame to the log, so the next time something goes
    missing there is a number to look at.

  * FIXED: THE MOD DID NOT LOAD ON SCRIPTHOOKVDOTNET 3.6 OR ON THE NIGHTLIES.
    "Could not load file or assembly 'ScriptHookVDotNet3, Version=3.9.0.0'". It was
    built against the 3.9 Enhanced fork, so the dll asked for 3.9 by name, and a
    3.6 or 3.7 host will not hand a script a ScriptHookVDotNet newer than itself.
    Every build since 0.1.3 said it ran on 3.6 and up; every report that it did
    was from somebody on the 3.9 fork.

    Built against 3.6.0 now, so every host is newer than the reference -- the case
    every script loader handles -- and the same dll runs on 3.6, the nightlies and
    the Enhanced fork. Reported by RReu and Van_Zandt, both on nightly 3.7.0.189.

    0.1.7 went up before this was built, so if you are on 3.6 or a nightly, 0.1.8 is
    the first version of this mod that loads at all.

  * Four members that 3.6.0 does not have were replaced with ones every supported
    build has -- the compile against 3.6.0 found them; the API check never knew to
    look. Nothing changes on the 3.9 fork.

  * 218 settings in the ini.

    (That line read 217 when 0.1.8 went out and the file held 218 -- the setting
    that matches the row to Bare Minimum's arrived without the count following it.
    Corrected here rather than left to be found by somebody counting.)


0.1.7
=====

  * FIXED: THE NOZZLE COULD NOT BE HUNG BACK UP. The prompt stuck on "Fill" at the
    pump. The walk back from the car forces the fill prompt for its whole length,
    so you arrived already latched to it -- and from there the old rule wanted the
    filler to be further than the pump by half a metre before it would offer
    hanging up. At a pump the two distances sit twenty to thirty centimetres apart,
    so on a snug park it was unreachable at any stance. Hang-up now wins the moment
    the pump is the nearer thing; the half-metre only guards the way back, which is
    what it was ever for. Reported by susipupi44.

  * Fixed: a jerry can or a fire extinguisher flashed into his hand for a frame when
    the nozzle was taken. Those are the two weapons the nozzle is held with -- one is
    equipped and hidden, and the nozzle hangs off the hand. The hide was applied
    before the weapon's object existed, so it hid nothing for a frame. The asset is
    now loaded before the weapon is selected.

  * Fixed: the same two showed in his hand during the grade card and the fill, and
    went when the nozzle was hung up. The hide was only being re-asserted while
    carrying the nozzle; anything that reselected a weapon during the fill -- another
    mod, usually -- left it visible for the rest of it. Kept hidden for as long as the
    nozzle is out. Reported by Gta5gamer__.

  * ELECTRIC VEHICLES ARE DETECTED BY THE MODEL'S OWN FLAG, not by a list of names.
    The list was nineteen names and already short an I-Wagen and two Inductors; it
    would have been short one car per DLC forever, and it could never have known an
    add-on car. The game's own FLAG_IS_ELECTRIC is read now, and it is on every
    ScriptHookVDotNet build this mod runs on -- checked, not assumed. The list stays
    underneath it as a safety net. Suggested by MaitreSystem.

  * Fixed: holding the fire button while pouring the can into a car poured a second
    stream onto the road from the same can. Every other stage with a can or a nozzle
    in his hand locked that button; this one did not.

  * Fixed: a pump can-fill interrupted part way -- a death, getting into a car --
    could leave the next can-fill off the nozzle crouched over a can on the floor.

  * The can's level is saved every ten seconds rather than only at shutdown, which is
    the one moment a crash never reaches. Same cadence as the tanks.

  * 217 settings in the ini, unchanged.


0.1.6
=====

  * FIXED: THE JERRY CAN STUCK AT 0 LITRES IN 0.1.5. It would not fill at a station
    and could not be siphoned into. If you are on 0.1.5, this is the reason to
    update. Reported by AliG_15.

    0.1.5 added a guard that puts back fuel the game hands out for free, because
    the can's contents are stored as ammunition and the game resets that on its
    own. The guard asked how much was in the can HE WAS HOLDING, when what it
    needed was the can HE OWNS -- and those differ the moment the can is on his
    back rather than in his hands.

    So holstering a full can read as zero, which the guard took for you having
    spent it, and it remembered nothing in the can. Taking the can back out then
    showed twenty litres of ammunition against a remembered nought, which is
    exactly what the game refilling it looks like -- so the guard dutifully put it
    back to empty, and saved that. Filling at a station repeated the whole cycle.

    A can.json written by 0.1.5 is now ignored rather than trusted, since the level
    in it was never true. Nothing to delete: the can starts again from whatever is
    actually in it.

  * Fixed: you could not siphon from a full car. A tank with no room in it ended
    the whole prompt, and took the siphon prompt down with the pour prompt -- so the
    one vehicle you would most want to help yourself from was the one vehicle you
    could not. Only pouring needs there to be room.

  * AN EMPTY JERRY CAN IS NO LONGER A DEAD ITEM. Reaching for one did nothing at
    all: the pour prompt gives up above zero litres and the siphon prompt was
    offered from inside it, so a can drained to nothing offered neither -- and being
    filled back up is the one thing an empty can is for.

    The interact key now puts it down as a real object on the floor rather than
    deleting it out of his hands, and the secondary key still siphons into it.
    Stand over it and the same key picks it back up with whatever was in it, which
    is the half that makes "put down" different from "thrown away" -- and standing
    near it holds off the sweeper, so it cannot vanish from under someone who is
    looking straight at it. DropEmptyCan = false leaves the whole thing alone.

  * FILL THE CAN AT A PUMP BY WALKING UP HOLDING IT. Filling a can used to need the
    NOZZLE out first -- the prompt lived beside "Hang the nozzle up" -- so the one
    errand where you are plainly carrying a jerry can was the one that made you pick
    up something else before it would talk to you.

    Walk up with the can and the secondary button offers it. He stands the can on the
    floor, takes the nozzle, and crouches over it to fill: the crouch is a full-body
    clip with the filling pose laid over the top as upper body, so his legs bend and
    the arm still reaches. He collects the can himself when it is done.

  * The grade card can be turned off from the settings menu rather than only from
    the ini. It was already a setting; it was not anywhere you could reach without
    opening a text file. Off fills straight away with the grade you last picked.

  * 217 settings in the ini, up from 215.


0.1.5
=====

  * Fixed: BIKES SPLUTTERED AT HALF A TANK. Reported three times, and three goes at
    the splutter threshold did not touch it, because the spluttering was never ours.

    The game keeps a fuel level of its own and this mod copies our litres into it, so
    that a car shot while empty does not spill a full tank across the road. The game
    reads that field against handling.meta, where a motorbike claims about sixty-five
    litres -- while the tank we give a bike is sixteen. So a brimmed bike was handed
    to the game as a quarter full, and one showing half on our gauge as about twelve
    per cent, which is where the game does its own spluttering.

    Bikes only, because bikes are the only vehicles whose tank we override. It is
    mirrored by fraction now, so both sides agree about how full the thing is however
    far the two capacities differ.

  * Spluttering starts later: six per cent of the tank, capped at 1.2 L. A sixteen
    litre bike now catches under 0.96 L rather than 1.6.

  * Fixed: THE SIPHON PROMPT WAS A BUTTON WITH NO WORDS NEXT TO IT. A help box holds
    about a hundred characters however many pieces it is fed in, and "Pour the can
    into the Sanchez (livery)   11.1 L" plus the siphon line came to a hundred and
    five. What fell off the end was the whole of "Siphon it out", while the button
    glyph in front of it sat safely inside the limit and drew.

    Long prompts are now shortened a word at a time, longest line first, so every
    prompt keeps its glyph and enough words to read. The pour prompt also puts the
    litres before the vehicle name, because what does not fit is dropped from the end
    and the name is the part already standing in front of you.

  * THE JERRY CAN KEEPS WHAT IS IN IT. Its contents are stored by the game as
    ammunition, and the game puts that back to full on its own -- after a respawn, an
    arrest, a mission, a reload. An emptied can came back brimmed, which is free
    fuel, which removes the reason to visit a station at all.

    The level is kept in scripts/Fumes/can.json, and only a station fill or a siphon
    may raise it. Pouring it on the floor as a weapon still empties it, because that
    is you spending it. RememberCan = false goes back to trusting the game.

  * 215 settings in the ini, up from 214.


0.1.4
=====

  * Fixed: a vehicle could come back from a save load with a FULL TANK when it had
    half of one. Two things have to go wrong together and a load is the one moment
    they both do. The tank is looked up by number plate, and a car that has just
    streamed in may not have its plate yet -- so the saved level is not found. At
    the same moment the game's mission flag is set while it restores itself, and
    the rule that hands a full tank to a car a mission gives you fires on that.

    The mission rule now needs a plate. A vehicle that cannot be identified cannot
    be known to be a mission vehicle, and "full" is the most damaging thing to
    guess about a car you do not recognise. Reported by sjmss8094.

  * BIKES GET A BIKE'S TANK. Sixteen litres rather than the sixty-five that
    handling.meta reports for them, so filling one costs about seventeen dollars
    instead of eighty.

    And they still go as far as a car. The economy figure is worked out from the
    tank size and the range together rather than listed, so a quarter of the fuel
    covers the same ground -- and if you change one the other follows.

  * ELECTRIC VEHICLES ARE OUT of the mod entirely. No tank, no gauge, no prompt at
    a pump, no fuel burned. A Voltic taking sixty litres of unleaded was the one
    thing in here that was simply wrong. AffectElectric turns them back on if you
    want the old behaviour. Asked for by MaitreSystem.

  * ALL THE STATIONS ARE ONE ENTRY on the map legend now, instead of one row each.
    The legend groups by name, so twenty-six forecourts were twenty-six of the rows
    you page through. The cost is that the row no longer names the brand or the
    district; BlipName blank gives that back. Asked for by enbee997.

  * Fixed: he filled up with the wrong hand. The nozzle was already in his right
    hand -- that setting only ever moved the prop, never the animation -- so the
    left arm did the reaching while the nozzle hung at his side. Reported by
    Zona Comics.

  * Fixed: the siphon and pour animations could stick. They ended in six different
    places and each was trusted to take the right clip off him; reloading the
    script mid-siphon took none of them off at all, because that path does not go
    through a stage change. The poses now come off by stage, the way the pump sound
    already did.

  * Spluttering is a share of the tank rather than a fixed number of litres. At
    0.6 L it was under one per cent of a saloon and nearly four of a motorbike --
    the smaller the tank the less warning you got, which is backwards. Capped, so
    no vehicle splutters for more than about two litres.

  * The spilled fuel pool grows with how much is on the floor, rather than reaching
    its full size in four seconds and then stopping. Nine litres now looks like nine
    litres.

  * The can he stands on the ground while siphoning is the same model he carries --
    the scuffed scenery can was a visibly different red next to the clean one on
    his back.

  * 214 settings in the ini, up from 207.


0.1.3
=====

  * RUNS ON ANY SCRIPTHOOKVDOTNET 3 FROM 3.6.0 NOW, including the nightlies and
    including the Enhanced fork. It used to need the fork and nothing else.

    The version was never really the problem, which is worth saying because the
    last release said it was. ScriptHookVDotNet is not strong-named, so the game
    loads it by name and ignores the version entirely - Fumes was always LOADING
    on stable. It called one method, Model.GetDimensions, that arrived after
    3.6.0, in five places: the nozzle, the filler guess, the can going down, the
    can in hand, the pump anchor. On stable that is not one failure, it is five,
    each one throwing the first time its own line runs, none at start-up, and none
    of them mentioning a version. That is worse than not loading.

    It goes through the native underneath now, and natives do not have versions.
    Every API the mod calls is checked against 3.6.0, a 3.7.0 nightly and the
    3.9.0 fork by a script in the repository, run before a release. That is an API
    check rather than a play-test, and the readme says so.

    GTA V Enhanced still needs the Enhanced fork - nothing else runs there at all.

  * A GRADE CARD AT THE PUMP. Point the nozzle at a car and pick your fuel on a
    panel that shows what each grade costs at THAT station and what it returns -
    "10% further" rather than a multiplier nobody can price. It wears the pump
    display's own frame and sits in the same place, so one becomes the other.

    Not shown for a diesel vehicle. There is nothing to decide.

  * CONTROLLER SUPPORT. The settings menu and the grade card both take a pad:
    D-pad moves, A accepts, B closes, LB and RB change page, and LB + D-pad Down
    opens the menu. The gauge positioner uses RB to resize and LT to step finely,
    since a pad has no Shift or Ctrl. Prompts name the buttons of whatever you are
    actually holding.

  * A proper wordmark on the settings panel, in fraktur.

  * SIPHON FUEL OUT OF ANY CAR. Walk up to a filler holding a jerry can and the
    second prompt draws fuel the other way -- out of their tank and into your can.
    He crouches, stands the can on the floor in front of him, and runs a hose from
    his hand down to its spout. Fill the can at a pump too, on the same button.

  * When the can is full it does not stop. The hose has no idea, so it keeps
    coming and a pool of petrol grows at your feet. It is the game's own petrol,
    which means it is the game's own petrol -- stand in it with a lit anything and
    find out.

  * You can throw a punch mid-siphon. The attack button stays disabled the whole
    time, because the thing in his hand is a petrol can with live ammunition and
    the trigger on one lays a trail of fuel across the forecourt. The press is
    read anyway and turned into an unarmed swing instead.

  * DIESEL. Trucks, buses, tractors and the fire engine take diesel, the pump
    display says so while it goes in, and it costs more and goes further. The game
    has no diesel flag on a vehicle -- there is no native that answers it -- so it
    is worked out from the vehicle class and corrected by name. Both override
    lists are in the ini: Service holds every bus AND the taxi, Utility holds
    tractors alongside the battery-powered Caddy, and Emergency has the fire truck
    next to eight petrol police cars.

  * Fuel grades. Regular, Plus and Premium, with the price and the economy both
    following. The grade lives IN THE TANK rather than in the setting, so a car
    you filled with premium last week is still running on premium -- otherwise
    flipping a menu row would change the mileage of every car you own, backwards
    through time.

  * Traffic pulls into forecourts. A low NPC already near a station drives in,
    sits at the pumps and drives off again. Deliberately NOT "low car goes looking
    for a station": stations are a median six hundred metres apart, the mod
    simulates a hundred and twenty, and a car sent that far despawns on the way
    every time. Keeping it alive would mean marking it a mission entity, and those
    are never reclaimed -- every low NPC would sit in the vehicle pool for the rest
    of the session.

  * A chime when you dip into reserve. Once per dip, not once per second.

  * The gauge moves with the car. The fuel sloshes faster and higher the quicker
    you go, throws to one side when you stop hard, and idles slowly at a standstill.

  * The gauge hides when the game's HUD does. Radar off, gauge off.

  * The pump icon moved outside the bar, onto a plate the width of the bar's own
    outline, matched to the height of the health and armour bars beside it.

  * Fixed: help text was losing a space at every line break. Long prompts are fed
    to the game in pieces and the game joins them with nothing between, so the
    space separating two pieces belonged to neither and vanished. Invisible in a
    sentence; not invisible when the break landed straight after a button icon and
    welded it to the word behind it. That is why the siphon prompt showed a button
    and no text.

  * Fixed: story-mission cars are full again, without DLC cars going back to being
    full. Those are two different kinds of script-owned vehicle and only one of
    them appears while a mission is actually running, which is the only thing that
    separates them.

  * Cars you left running catch up on the fuel they should have burned while you
    were away, rather than only burning it while loaded.

  * Settings menu: icons, pages, and a live positioner for the gauge.

  * Fumes says its hotkey on start-up, like everything else does.

  * The hose you see is drawn rather than roped, and both hoses match: same
    thickness, same flat black, same hang.

  * 207 settings in the ini now, up from 118, every one of them commented with why
    it is there and what happens if you change it.


0.1.2
=====

  * IF IT WAS NOT LOADING FOR YOU, READ THIS FIRST. The requirements line said
    "ScriptHookVDotNet 3 (3.9 or later)", which is true of the dll and useless as
    an instruction: there is no release called 3.9. The build carrying assembly
    version 3.9.0.0 is the ENHANCED FORK, released as v1.1.x. So people searched
    for a 3.9, found nothing, installed the newest thing labelled 3, and got
    silence. Both numbers are right and they are not the same number, and nothing
    here said so. It is named outright now, with the link, and there is an
    IF IT IS NOT LOADING section that narrows it in the right order.

        https://www.gta5-mods.com/tools/script-hook-v-net-enhanced

  * Fixed: the prompt bounced between "fill" and "hang up" and neither could be
    pressed. Standing at a pump the two distances come out twenty to thirty
    centimetres apart, so "whichever is nearer" flipped on every step and every
    sway of the camera. A choice now has to be beaten by half a metre before it
    is replaced. Reported by DirtCheap1.

  * Fixed: DLC and online vehicles always arrived with a full tank. Anything
    script-owned was being treated as "handed to the player deliberately, so fill
    it" -- which is also true of everything a trainer spawns, and spawning is how
    anyone gets at those cars. Their tank SIZES were always right; only the fill
    was wrong. Reported by BlueLion.

  * Refuel from a jerry can. Walk up to a filler carrying one and it offers to
    pour. Slower than a pump on purpose. The can's ammo IS its fuel, so one half
    emptied making a trail is half empty here too. Asked for by jerome74 and
    DirtCheap1.

  * Cars you have driven and left running keep burning fuel while they are
    loaded, not just the one you are in or last got out of.


0.1.1
=====

  * The settings menu names its pages across the head -- HUD, FUEL, STATION,
    HOSE, current one lit -- instead of reading "HUD 1/4". The number sat in the
    same column as the ON, OFF and 0.72 beneath it and read as a value belonging
    to the row under it. A label that has to be explained is not a label.

  * Fixed: leaving the gauge positioner with the menu key threw the placement
    away. It stayed where you put it for the rest of the session and the ini
    never heard about it, so it sprang back on the next reload with nothing to
    explain why. Enter saved and the menu key did not; both do now.

  * Fixed: the positioner read its two exit keys as `a || b`, and || short
    circuits -- so on any frame Enter produced an edge, Backspace's edge was
    never evaluated. That call is also what updates the remembered key state, so
    a Backspace held through that frame stayed recorded as up and would register
    a phantom press later.

  Note: the 0.1.0 asset was replaced in place after it was published, so a copy
  downloaded early does not match one downloaded late. That is what this version
  number is for, and it will not happen again -- anything that changes after a
  release goes out gets a new one.


0.1.0
=====

First release.

  * Persistent fuel for every vanilla and online vehicle. Tanks are saved per
    vehicle and survive a save, a reload and a session.

  * A refuel you walk through rather than a menu: take the nozzle off the pump,
    carry it on a real physics rope, fill at the model's actual filler, walk it
    back and hang it up. Walk too far and it is pulled out of your hands.

  * The nozzle is a real prop in your hand, held on an invisible weapon so the
    pose is right, and it goes back to melee when you hang up.

  * Pump display on the forecourt: brand, price, litres, running total, and a
    sight glass with the fuel rising in it.

  * Fuel gauge beside the minimap. Colour ramps yellow to red with the level,
    bubbles rise through it, and the surface moves.

  * Money is really taken, and the charge is read back rather than assumed --
    Player.Money is a no-op on non-protagonist models, and a bill nobody paid is
    worse than no bill.

  * Pumps are found as OBJECTS, not by coordinate, so the mod works at
    forecourts it has never heard of. It also corrects its own station list from
    the pumps it finds, into a local file an update cannot overwrite.

  * Empty means empty: the engine dies, and an electric car goes flat rather
    than dry.

  * 25 stations, each with its own price.

  * A running-fuel sound while filling. GTA has no fuel-pump sound of its own --
    vanilla has no refuelling, so one was never authored -- so this borrows the
    car wash spray, which is pressurised liquid on a loop. If it will not play,
    Fumes works out that it did not and moves on rather than going quiet with no
    explanation.

  * Both GTA V editions from one build. No asset mods, no OpenIV, no RPF edits,
    and no dependency beyond ScriptHookVDotNet itself.

  * A settings menu on Shift + F, built out of rectangles rather than a menu
    library, so it stays a mod with no dependencies. Changes apply as you make
    them and are written back to the ini when you close it.

  * A live gauge positioner in that menu. Where the minimap lands depends on the
    safe-zone slider and the aspect ratio and a mod cannot ask, so the gauge can
    only ship right for one screen; now it can be dragged into place on yours,
    with the size shown in real pixels as you do it.

  * The hose is one of the game's eight ropes and you can pick which. NumPad *
    with the nozzle in hand steps through them, NumPad 0 keeps the one you are
    looking at.

  * A rope type that crashes the game is remembered across the crash and never
    offered again -- written down before the call that might crash, and read back
    on the next launch.
